# 0001 — 物差しを works から分けて、このリポジトリに置く

## 状態

採用 (2026-09-24)

## 文脈

mokume-metal/works は mokume で作った**作品例**を置くリポジトリで、README は「作品は
測る口を持たない」と決めていた (works#39・works#40)。ところが works の中に物差しが 3 本
育った。

- **Atlas**: Processing の例 157 本の語彙を数える台帳
- **Probe**: 約束が期待どおりに出るかを 1 枚の絵で突く
- **Drift**: 同じことを動きで突く

その結果、works の README には物差しのための例外の但し書きが増えた (並べ方の節、`Tests/` を
持つものの一覧、「Probe と Drift を除く 14 作品」)。scripts にも、台帳 (`checks.json`) の
ためだけの分岐が残っていた。作品を読みに来た人が最初に出会うものではない、という works の
判断とも逆向きだった。

## 決定

物差し 3 本を works から写し、このリポジトリに置く (probes#1)。works からは消す
(mokume-metal/works#100)。

- **履歴は持ち込まない。** 両リポジトリとも squash merge なので、`subtree split` で履歴を
  運んでも PR のマージで 1 つに畳まれる。写した時点の works のコミット (`68306a8`) を
  README と commit に書き、移す前の履歴は works で辿る。
- **scripts は写して、それぞれに合わせて削る。** 共有のパッケージにはしない。2 リポジトリの
  ために配布の仕組みを増やすより、写した数百行の重複のほうが安い。
- **mokume との関係は works と同じにする。** 依存は一方向で、あちらはこのリポジトリを参照
  しない。新しい版に気付くのは、こちらの `mokume-watch.yml` が日次で見に行く形で行う。

## 影響

- works の作品は、測る口を持たない例として読める形に戻った。
- `scripts/` の写しは片方だけ直すとずれる。特に `mokume_api.py` の名前の起こし方は
  Atlas の台帳の区分に効くので、変えるときは両方を直す (CLAUDE.md にも書いた)。
  写したときに持ってきた不具合もある (#6 = works#98)。
- mokume 側の Issue のうち、Probe・Drift が起票した 14 件は works の PR (works#97・works#99) を
  指したままである。PR は残るのでリンクは生きており、各 Issue に移ったことを書き足した。
