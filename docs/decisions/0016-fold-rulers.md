# 0016 — 古い版に固定した物差しを畳み、新しい口を突く 4 本だけで mokume の版を追う

## 状態

採用 (2026-11-11)

## 文脈

2026-11-11 の時点で、13 本の物差しのうち 11 本が mokume `v0.16.2` に固定され、本体は `v0.45.0` まで進んでいた。
版上げの Issue (#70) は 2026-10-04 から開いたままで、mokume#3871 が入れば `MokumeHost` への移行 (#83) も
版上げのたびに要る。

- 固定した古い版を回し続けても、新しい破れは見つからない。見つかるのは版を上げて新しい口を当てたときだけである
  (Clause を `v0.35.0` へ上げて mokume#3223 を見つけた)。
- 直った件の回帰は、mokume 側で Bug を直した PR が持つテストが見張る。0.16.2 の上で `withKnownIssue` が赤くなる
  のを待つ意味は薄い。
- それでも 13 本ある限り、版上げのたびに 13 本ぶんの手間がかかり、結果として誰も上げなくなっていた。

## 決定

**残す 4 本で mokume の最新版を追い、残りの 9 本は畳む。** メンテナが #84 で決めた。

| 扱い | 物差し | 理由 |
| --- | --- | --- |
| 残す | Clause・Routine | 新しい口を、約束の文 (Clause) と作品の書き方 (Routine) から突ける |
| 残す | Atlas・Reach | 破れを探す物差しではなく、Processing の口がどこまで届くかの台帳。畳むと網羅の数が版とともに更新されなくなる |
| 畳む | Probe・Drift・Aftermath・Lattice・Weave・Churn | 突いた候補を人が選んだ 1 回きりの記録で、戻した件は直り終えた |
| 畳む | Soak・Tumble・Imprint | 版が進めば新しい口を拾えるが、版上げの手間に見合わない。新しい口は残す 4 本で突く |

- **畳むとは、ディレクトリを消し、ルートの README の「畳んだ物差し」の表に 1 行残すこと**である。行には、
  畳む直前のコミット (`9b771a1`) の木へのリンクと、名指ししていた mokume の Issue を書く。
- **畳む前に、名指ししていた mokume の Issue に回帰を見張るテストがあるかを確かめる。** 76 件すべてが閉じており、
  70 件は mokume の `Tests/` がその番号を名指しし、残る 6 件は重複先の検査・PR が足したテスト・docs か設計の
  Issue だった。見張りの無い Bug は 0 件で、mokume へ移す再現は無かった (#84 のコメントに表がある)。
- 畳んだ物差しの ADR (0005・0008〜0011・0013・0014) は消さず、状態に畳んだことを書き足す。判断の理由は、
  戻すときにまた要る。

## 結果

- 版上げは 4 本ぶんになる。`scripts/stress.py` が回すのは画素を見る 2 本 (Routine・Reach) になる。
- 代償として、畳んだ観点 (フレームをまたぐ継ぎ目・条件の格子・機能の組み合わせ・資源・失敗の後・書き出し・
  乱数の列・動かし続けた絵) は、新しい版の上ではもう測られない。
- 要るときは `git checkout 9b771a1 -- <物差し>` で戻し、`scripts/bump.py` で最新版へ上げてから測る。
  戻した物差しは `stress.py` の `RULERS` などにも足し直す。
