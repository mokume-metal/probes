# 0006 — 約束の破れ探しから、実装が適切に動くことの徹底した検証へ広げる

## 状態

採用 (2026-09-25)

## 文脈

probes の物差しは、約束の破れを見つける力を持っている。mokume へ戻した Issue は 38 件
(うち 32 件が open) で、幾何・線・字のずれ、引数の境界値、フレームをまたぐ継ぎ目、資源の
漏れが中心である。

一方、mokume の**重大なバグはほぼ probes の外で見つかってきた**。見つけた経路は、mokume
内部での実測やコードの読み (約 133 件) と、works の作品制作 (約 33 件) である。

| 種類 | 例 |
| --- | --- |
| ハング | 最小化・ディスプレイのスリープで止まる (mokume#223・#874)、watch が `write` で塞がる (#1296) |
| クラッシュ | 並列で動かすと `Canvas.deinit` で SIGSEGV (#261)、巨大な面で Metal のアサーション (#885) |
| GPU 同期 | 影のバリア抜け (#341、59 回中 2 回)、FrameSync (#1063、1392 件中 1 件) |
| 失敗の後の汚染 | flush が途中で投げると以後 createGraphics が作れない (#1179)、描けなかった図形が次のフレームに出る (#342) |
| 戻らない劣化 | 字形の面が満杯になると以後の字が永久に出ない (#1342)、fps が 2 に落ちて戻らない (#370) |
| データ破壊 | SIGTERM で動画が壊れる (#1219)、壊れた PNG が正式な名前で残る (#1341) |

物差しがこれらに届かなかった理由は、構造にある。

- **動かす条件が 1 点に固定されている。**
  - ヘッドレスの `advance()` で回す。
  - 面は 160² 前後、`pixelDensity` 1、30 fps。
  - 時計はフレーム番号から導き、入力は台本。
  - debug で組み、Mac 1 台で回す。
- **正誤の判定が mokume 自身の別の経路に頼っている。** 両方の経路に共通する誤りは見えない。
- **窓・書き出し・プロセスの寿命を測っていない。** mokume 自身の検査も、ここは 0 件である。
- **失敗の後を見ていない。** 正常系しか通っていない。
- **各検査を 1 回しか回さない。** 稀な失敗が見えない。

読まずに書き方から選んだ Routine が 0/25 だったことは、ありふれた書き方の同類を足しても
得られるものが小さいことを示している。

## 決定

**probes の目的を「約束の破れを見つける」から「mokume に実装されたものが適切に動くことを
徹底的に確かめ、mokume へ戻す」へ広げる。**

- **重大度で優先する。** ハング・クラッシュ・データ破壊・戻らない劣化・GPU 同期と並行性を、
  見た目の小さなずれより先に測る。
- **判定を mokume の外に置くことを優先する。** 使うのは次のものである。
  - mokume が約束している性質: 決定論 (mokume ADR-0001 原則 2) など
  - 関係による判定 (metamorphic)
  - 解析解
  - 原典 (Processing・p5)
  - 旧版
- **条件の空間を 1 点から広げる。** 反復・同時実行・検証レイヤ、面の大きさ・倍率・fps・
  組み方、窓とプロセスの出来事、失敗の後、長時間を扱う。
- **観点の地図は親 Issue (#26) に置く。** 観点 1 つを Issue 1 本にし、測り方の判断は
  観点ごとの ADR に残す。
- **外から起こせない失敗は、提案として mokume へ戻す。** GPU の中断のように公開 API から
  起こせないものは、probes の `@testable` を使わない方針を崩さず、mokume 側のテストの
  守備範囲として起票する。
- 戻し方は変えない。mokume の不具合は mokume へ起票し、こちらの検査は
  `withKnownIssue("mokume#NNNN: …")` で名指しする。

## 影響

- 物差しを 1 本ずつ足す形 (ADR-0003・0004・0005) に加えて、**既存の物差しを別の条件で回す
  道具** (#19) や、**プロセスとして外から操る物差し** (#21) が入る。
- 検証レイヤ・反復・長時間の実行は Metal と時間が要り、CI では回らない (ADR-0002)。
  どこで定期的に回すかは、#19・#22・#23 を進める過程で決める。
- 物差しの README の「何件を突いて何件が破れていたか」に加えて、**何を何回・どの条件で
  回したか**も記録に残す。
