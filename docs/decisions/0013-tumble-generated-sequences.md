# 0013 — 乱数から作った呼び出しの列で突く物差しを別に立て、判定を mokume の別経路に頼らない 7 つにする

## 状態

採用 (2026-09-27)

## 文脈

これまでの物差しは、候補を人が選んでいた。

- Probe・Drift・Weave は、ソースを読んで継ぎ目に当たりを付けた。
- Routine は、作品がふつう書く書き方を 25 通り選んだ。破れは 0 件だった。
- Lattice は、条件の格子を人が決めた。

どれも、人が思い付いた組み合わせしか突けない。一方、mokume の重大なバグには、極端な値や長い組み合わせで
はじめて出るものがある (mokume#1342 の字形の面が満杯になる・Soak の落ちる口 mokume#1587–#1590)。
#26 の観点の地図の #23 (API の呼び出し列のファジング) がこれにあたる。

## 決定

**物差し `Tumble` を足す。**

- **既存の物差しに足さず、別の 1 本にする。** 候補を人が選ばないので、「何件を突いて何件が破れていたか」の
  数え方が違う (種の数で数える)。ADR-0003・0005・0008・0011 と同じく、混ぜずに数える。
- **列は種 1 つから決まる。** 乱数は SplitMix64 で、同じ種からはどの機械でも同じ列が出る。破れた列は
  種 1 つで呼び戻せる。
- **口録 (`Catalog`) は、作品がふつうに呼ぶ口を 110 余り並べる。** 引数は種類ごとに、ふつうの値の幅と
  端の値の袋を持つ。端の値は 0・負・とても大きい・とても小さい・数でない値・無限で、引数の 1 割前後に出す。
  - ファイルを読み書きする口と、フレームの進み方を変える口 (`noLoop` など) は外す。前者は Imprint が見る。
  - 形を並べる口 (`beginShape` 〜 `endShape`) は、開いて閉じるまでを 1 口にする。開いたまま残すと、
    既知の mokume#1591 を踏み続ける。
- **判定は 7 つにし、どれも mokume の別の経路に頼らない。**

  | 判定 | 破れ | 出典 |
  | --- | --- | --- |
  | 落ちない | プロセスが signal で死ぬ (`crash`) | 描く口は投げない (mokume ADR-0020 決定 5)。落ちるのは投げるより悪い |
  | 止まらない | 出力が 20 秒進まない (`hang`) | 同上 |
  | 投げない | `advance()` が投げる (`threw`) | 同上 |
  | 毎回同じ絵 | 同じ列を 2 回回して、どこかのフレームの画素がバイトで違う (`nondeterministic`) | mokume ADR-0001 原則 2 |
  | 戻らない劣化が無い | 列の後の番兵が、列を回さなかった番兵と違う (`sentinel`) | フレームを越える状態は明示して戻せ、越えない状態は境目で戻る (mokume ADR-0021 決定 4) |
  | 絵が数である | 画素に数でない値か無限がある (`nonfinite`) | 数値の口は非有限を受け口で弾く (mokume ADR-0033 決定 9・ADR-0035) |
  | 漏れない | 列を 240 枚繰り返して、footprint か GPU の確保量が増え続ける (`leak` / `gpuLeak`) | Soak と同じ (ADR-0005) |

  - **番兵**は、列が触りうる状態のうちフレームを越えるもの (塗り・線・混ぜ方・字・貼る絵・断片・露出) を
    明示して既定へ戻してから、決まった絵を描く。フレームを越えないもの (変換・切り抜き・光・効果・視点) は
    戻さない。mokume が境目で戻す約束なので、戻らなければ破れである。
  - **陰性対照を置く。** 状態を変える口をふつうの値で並べた列は、番兵で破れない。番兵から戻す行を 1 つ
    抜くと赤くなる。
- **漏れは判定と別に回す** (`--soak`)。1 種に 240 枚回すので、判定より 1 桁遅い。
- **落ちる・止まるは、子プロセスの終わり方で見る。** 1 本の子プロセスで種を束で回し、回す前に種を名乗らせる。
  落ちたら最後に名乗った種を記録し、次の種から新しい子プロセスで続ける。止まったとみなすのは、束全体の
  制限時間ではなく、出力が 20 秒進まないときにする。止まった列が確保を積み続けるからである (種 3161 は
  130 秒で 21 GB に達した)。
- **縮小器は delta debugging にする。** フレームを落とす → 口を落とす (塊から 1 つずつ) → 端の値をふつうの
  値へ戻す、を変わらなくなるまで繰り返す。1 回の試しは子プロセス 1 本である。
- **ドライバ (`Tumble/scripts/tumble.py`) は Python で、物差しの中に置く。** 子プロセスの終わり方と時間を
  外から見るのは、Swift Testing の exit test より素直である。ルートの `scripts/` は works の写しなので
  (CLAUDE.md)、そこには置かない。
- **起票済みの破れを踏む引数は、生成で避ける** (`Catalog.avoidKnown`)。踏むたびに落ちると、その先の列が
  回らず、同じ既知の破れで結果が埋まる。避ける引数には Issue の番号を書き、直ったら外して見張りに戻す。
  避けていることは `GeneratorTests` が押さえる。
- **成分に数でない値を持つ色は、袋に入れない。** 0–1 の口 (`LinearRGBA(straightRed:…)`) で直に作った色は、
  受け口で弾かれずに絵に届く。mokume は直に作った値の扱いを変えないとしている (mokume ADR-0033 決定 3)。
  入れると、利用者が自分で作った NaN が絵に出ただけのものが `nonfinite` を埋めた (400 種のうち 26 種)。
- **`swift test` は固定の種の束だけを回す。** 破れを探すのは `tumble.py run` で、数千種を回すのに十数分
  かかる。`swift test` が押さえるのは次の 4 つである。
  - 判定が効いていること (陰性対照)
  - 固定の種の束 (0..<48) が破れないこと
  - 縮めた列 (`Findings/`) の破れ
  - 起票した再現 (`Repros/`)

  直ったときは、他の物差しと同じく `withKnownIssue` が赤くなって知らせる。
- **画素を見る物差しとして `stress.py` に入れる。** 指紋は `Examine` が取った FNV-1a をそのまま書く。

## 影響

- 版上げのたびに `tumble.py run` を回すと、口録の範囲で新しく入った破れに気付ける。口録に無い口は突けない
  ので、版上げで増えた口 (`api-diff.py`) は口録にも足す。
- 見つかる破れは端の値に偏る。ふつうの値だけの組み合わせは Routine と Weave が見る。
- 1 回目 (mokume `v0.12.1`) の結果と起票は [Tumble/README.md](../../Tumble/README.md) にある。
