# 0003 — リファレンスの側から届く口を測る物差し (Reach) を足し、起票は実需と規範に限る

## 状態

採用 (2026-09-24)

## 文脈

Processing・p5.js でよく使う口を mokume がどこまで網羅しているかを確かめたい、という依頼が
あった (probes#11)。既にある物差しでは測れない。

- **Atlas** は Processing の *Examples* 254 本を当てた台帳で、例に出てくる語彙しか見ない。
  角の丸い `rect`・`arc` の閉じ方・1 行の `bezier()`・`randomGaussian`・`cursor`・`erase` のように、
  例には出てこないが作品を作り始めるとすぐ使う口は、台帳に行が無い。
- **Probe / Drift** は約束の破れを突く検査で、網羅は見ない。

一方で、網羅の穴を見つけても、それだけでは mokume に足してもらう理由にならない。mokume は
機能を実需で足すと決めていて ([mokume ADR-0022](https://github.com/mokume-metal/mokume/blob/main/docs/decisions/0022-production-track.md) 決定 6)、
「一般にそういう API があるから」を認めない。Atlas の計数だけを根拠にした
[mokume#902](https://github.com/mokume-metal/mokume/issues/902) (QUADS) は、「移植して困った
作品はまだ無い」として not planned で閉じられた。網羅の物差しから Feature を量産すると、同じ形で
閉じられる Issue を量産することになる。

## 決定

### 1. リファレンスの側から口を並べる物差し `Reach` を足す

- 手本の口 1 つを 1 タイルにし、**実際に mokume で書く**。コンパイルが通ることが「口がある」の
  証明になり、`swift test` は届くと判定した口が描いて画素を置くことを確かめる (窓の経路と、
  窓を出さない経路の両方)。
- 判定は Atlas と同じ 7 区分 (`same` / `renamed` / `host` / `drop` / `write` / `bend` / `none`)。
  読み比べられるように語彙を増やさない。
- `none` のタイルは口を呼ばない。書けないものを書けたように作り替えると、止まったこと自体が
  消える (Atlas と同じ態度)。
- 一覧は Swift のソース 1 か所に置き、README の表はそこから起こしてテストで突き合わせる。
  手で書いた表は、一覧を直したときに必ずずれる。

### 2. mokume への起票は、実需か規範に限る

Reach で見つけた穴は、次のどちらかを示せるときだけ mokume へ起票する。

| 認める | 数え方 |
| --- | --- |
| 実需 | **works の作品 2 本以上が、同じものを手で書いている。** mokume ADR-0020 決定 7 の改訂 (2026-09-22) が `lerp` / `constrain` を足したときの数え方をそのまま使う |
| 規範 | mokume の既にある ADR から導ける欠け。手本と同じ名前で別の体系の数を運ぶ (ADR-0020 決定 1 の改訂・ADR-0034)、手本と名前がずれていて理由がどこにも無い (ADR-0020 決定 1) など |

どちらにも当たらない穴は、Reach の README に「起票しなかったもの」として理由と一緒に残す。
作品の側が踏んだときに、そこから引ける。

**Atlas・Probe・Drift・Reach は作品に数えない** (mokume ADR-0022 決定 6 の「`Sketches/` で
踏んだものは実需に数えない」と同じ理由 — 物差しは面から逆算して書かれる)。

## 影響

- 最初の測定 (mokume `v0.11.1`) で、works の 13 作品 (`22387ce`) と突き合わせて 6 件を起票し、
  1 件にコメントした (Reach/README「mokume へ戻したもの」)。QUADS は #902 が「実需が来たら新しい
  Feature で立て直す」と決めていた条件を、5 作品で満たしていた。
- **Reach は穴が埋まっても赤くならない。** Probe・Drift の `withKnownIssue` のような仕掛けを
  持たないので、版上げでは `scripts/api-diff.py` で増えた口を一覧と突き合わせる
  (`.claude/skills/probes-bump/`)。
- works の作品を数える作業は手で行った。作品が増えると数え直しが要る。道具にするかは、
  2 度目に同じことをしたときに決める。
