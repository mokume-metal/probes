# 0008 — 失敗を起こした後のフレームを、失敗させなかった参照と比べる物差しを別に立てる

## 状態

採用 (2026-09-25)

## 文脈

mokume の重いバグの 1 つの型は、**失敗の後に以後のフレームが汚れる**ことである。

- mokume#342: 描けなかったフレームの図形が、次のフレームでもう一度描かれる
- mokume#1179 / #1180: flush が途中で投げると、以後 createGraphics が作れない
- mokume#1183 / #1184: 投入を前提に確定させた記帳・開いたままの encoder が残る

どれも mokume 内部のコードの読みで見つかった。probes の物差しはどれも正常系しか通って
おらず、失敗の後を測っていなかった (#26、ADR-0006)。

mokume の公開 API を洗い出した結果、次のことが分かった。

- `Sketch.draw()` は投げられない。
- スケッチが意図して起こせる失敗は 3 系統に分かれる。
  1. 資源の生成が型のついたエラーを投げる
  2. フレームの途中で放り出した状態 (閉じない形・`endDraw()` の無い描き場所・`pop()` の無い `push()`)
  3. 検めずに通した値 (NaN・無限・焼き場のあふれ)

## 決定

**物差し `Aftermath` を足す。**

- **既存の物差しに足さず、別の 1 本にする。** 当たりの出どころ (失敗の経路) も判定の型
  (失敗させた経路 ↔ 失敗させなかった経路) も、Drift・Routine と違う。ADR-0003・0005 と
  同じ理由で、「何件を突いて何件が破れていたか」を混ぜずに数える。
- **判定は、失敗させた経路 (`suspect`) と、失敗させなかった参照 (`reference`) の比較にする。**
  - `suspect` は 2 枚目で失敗を起こす。`reference` は同じフレームで失敗の行を抜くか、
    正しい行に置き換える。
  - 失敗したフレームも番号と時刻を消費する。そのため、参照も同じ枚数を回し、乱数の消費も
    揃える。
  - 比べる許容はほぼ 0 にする (成分の差 0.004)。同じ機械・同じフレーム番号ならバイト単位で
    同じ絵が出る約束 (mokume ADR-0001 原則 2) を使う。
- **資源の生成が投げる候補は、陰性対照として 0 画素差を求める。** 資源の生成は型の
  ついたエラーを投げる (mokume ADR-0020 決定 5)。投げた口が状態を汚さないことは、それ
  自体が本丸の約束である。**投げたことも数えて押さえる** — 投げていなければ、陰性対照として
  何も言えない。
- **失敗が本当に起きたことを、対照で押さえる。** 例えば次の 2 つである。
  - 断片の拾い直し: 組める中身へ書き換えると絵が変わる。
  - 焼き場のあふれ: 毎フレームあふれさせた版では同じフレームの字が落ちる。
  起こしたつもりの失敗が起きていないと、一致しても何も言えない。
- **約束の出典が書かれているものだけを候補にする。** 期待が説明から一意に決まらない当たり
  (上限を超えた粒の力・`emit` の無限の範囲) は突かず、README に理由を残す。
- **GPU を故意に打ち切る当たりは突かない。** 機械ごと巻き込み、mokume#1065 の完了条件も
  故意のハングを禁じている。外から起こせない失敗なので、mokume 側のテストの守備範囲として
  戻す (ADR-0006)。
- **落ちる口 (プロセスの終わり方) は Soak が持つ。** Aftermath は画素で判定できるものだけを
  扱う。
- **1 経路 = 1 本のスケッチ、経路ごとに別の `SketchRuntime`** (ADR-0003 の Routine と同じ)。
  ランタイムそのものや書き出しを失敗させる候補は、テストだけに置く。
- **版は `v0.11.2` で始める** (他の物差しと同じく、測る版で始める)。

## 影響

- mokume `v0.11.2` で 16 件を突き、2 件が約束を破っていた。どちらも Bug として起票した。
  - `endDraw()` の無い描き場所で変換が積み上がる (mokume#1622)
  - 数でない力で生きている粒がすべて消える (mokume#1623)
- 資源の生成が投げる 8 通りと、ランタイム・書き出し・断片の拾い直しの失敗は、どれも
  1 画素も汚さなかった。mokume#1179・#1180・#342 の直しが、外から見ても効いている。
- 画素を見る物差しなので、`Stage.swift` で読んだ絵は `fingerprint` を通す。
  `scripts/stress.py` の対象にも入れた (ADR-0007)。
- 版上げでは、他の物差しと同じく「赤くなった `withKnownIssue` は直った約束」として読む
  (`.claude/skills/probes-bump/`)。
