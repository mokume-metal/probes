# 0003 — 中身を読まずに、作品の書き方から当たりを付ける物差しを別に立てる

## 状態

採用 (2026-09-24)

## 文脈

Probe と Drift は、mokume のソースを読んで当たりを付けた物差しである。読んだから見つかった
破れ (14 件) は、どれも継ぎ目の奥にあった — 鏡映した立体の裏面、噴き口どうしの繰り越し、
描き場所だけ止まる時刻など。

この当たりの付け方は、**実装が気にしている場所に寄る**。作品を書く人は実装を読まずに、
Processing や p5 で覚えた書き方をそのまま持ち込む。`setup` で色を決めて `draw` は描くだけ、
半透明の矩形で残像、`pmouse` のお絵描き、`scale` の脈、`sin` で揺らす大きさ。その
ありふれた組み合わせが動かしても崩れないかは、どの物差しも正面から測っていなかった。

## 決定

**物差し `Routine` を足す。** 候補は mokume の中身を読まずに、作品の書き方から選ぶ。

- **Drift に足さず、別の 1 本にする。** 当たりの出どころが違う (ソース ↔ 書き方) ので、
  README の「どうやって当たりを付けたか」が混ざる。結果を読むときに「読んで狙った破れ」と
  「ふつうに書いて踏むもの」を分けて数えたい。
- **mokume から読むのは、公開 API 一覧と、食い違いが出た後の説明文・ADR だけ。** 名前を
  知らないと書けないので API 一覧は読む。説明文は、食い違いが約束の破れか設計かを分ける
  ためにだけ読む。先に読むと、Probe と同じく実装が気にしている場所へ寄る。
- **期待は原典 (Processing・p5) から立てる。** 食い違ったら mokume の説明を読み、
  約束があれば「原典と違うが約束どおり」、約束が無ければ docs として起票する。
- **1 経路 = 1 本のスケッチ、経路ごとに別の `SketchRuntime`。** Drift のように 1 枚の面を
  分け合うと、`setup` の描き方や面全体の塗りが隣へ漏れる。窓も経路ごとの舞台の絵を
  読み戻して貼る。読み戻しが 1 経路あたり約 10 ms かかるので、窓は 1 候補ずつ見せる。

## 影響

- v0.11.1 で 25 件を突き、約束の破れは 0 件だった。期待と違った 3 件はどれも説明か ADR が
  決めている振る舞いで、説明に無かった 1 件を docs として起票した (mokume#1550)。
- **いまの振る舞いを押さえる検査が 3 件ある** (`trailBackground`・`negativeSize`・
  `polylineTrail`)。mokume が説明や ADR を改めると赤くなるので、版上げの手順
  (`.claude/skills/probes-bump/`) では「直った約束」と並べて「変わった振る舞い」として読む。
