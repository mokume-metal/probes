# 0012 — mokume への起票は走らせたものから組み、骨格を欠く起票を CI で落とす

## 状態

採用 (2026-09-26)

## 文脈

物差しが見つけた破れは、mokume へ Issue にして戻している。約 80 件を調べた (#43)。

項目がそろっているかで見れば、probes 由来の起票は mokume の中でもよい部類に入る。環境は 94%、Swift の再現は 94% に付いていた。弱かったのは、本文だけで話が閉じていないことと、書いてあることを確かめられないことである。

- **再現が走らない・ずれる。** 貼っていたのは `draw` の中身の断片で、そのまま走るものではなかった。検査を手で書き写すので、走らせたコードとずれた (mokume#1638。#40 で検査を直した)。
- **辿れない。** リンク先は、物差しを入れた PR か probes のトップだった。数字の測り方は probes の中にしかなく、commit で固定したリンクは 0 件だった。
- **環境が欠ける。** Xcode と Swift の版は 0 件。組み方 (debug か release か) も書いていなかった。
- **起票の時点に絵が無い。** 動く事象に、起票の時点で動画を付けた件は 0 件だった。絵を出す手順は #41 で決めた (skill `probes-evidence`)。
- **調べきる前に出した。**
  - 読んだだけで走らせずに起票した (mokume#1607)。
  - 物差しをまたいで、同じ根の件を重ねて起票した (mokume#1647)。
  - トリアージで主張や再現を訂正した件が 12 件ある。
- **報告とトリアージが混ざる。** 本文に後から棚卸しが足され、起票したときの報告がどこまでだったか読み分けられない。

根は 3 つだった。約束が版上げの手順の片隅 (probes-bump の 7 行) にしかなかったこと、起票に載せるものを走らせたものから出していなかったこと、誰も検めなかったことである。

## 決定

- **起票に載せるものは、走らせたものから出す。** 再現・その出力・環境・出どころのリンクは `scripts/filing.py` が出す。人や AI が書くのは、事象・期待・当たり・判断だけにする。
- **再現は probes の中のファイルとして置き、検査が走らせる。**
  - 置き場は `<物差し>/Tests/<物差し>Tests/Repros/<鍵>.swift`。
  - mokume と Foundation だけで閉じ、`static func reproduce() throws -> String?` を持つ `enum` を 1 つだけ置く。
  - 物差しの `ReprosTests` は、このファイルを `withKnownIssue` で包んで走らせる。
  - 本文には同じファイルを貼る。これで、本文のコードと走っているコードが食い違わない。
  - `filing.py repro` は、同じファイルを mokume だけに依存するパッケージに組んで走らせる。版を固定したものと `main` の両方で走らせる。
- **本文の骨格を決め、印で囲む。**
  - 区間の印は `<!-- probes-filing:begin v1 -->` と `<!-- probes-filing:end -->` にする。
  - 見出しは 事象 / 再現 / 期待と実際 / 証跡 / 確かめたこと / 当たり / 出どころ / 環境 の 8 つ。
  - 区間の中は起票したときの報告として凍結する。後の判断はコメントか区間の後ろへ書く。mokume の運用は縛らない。
- **起票の前に調べきる。** 「確かめたこと」には次の 5 つを書く。確かめていないものは空欄にせず、`未確認: 理由` と書く。
  - 単独の再現
  - main でも出るか
  - 反復
  - 陰性対照・境界
  - 重複
- **証跡は GitHub の添付に上げる。**
  - 見た目の事象には、比べる絵を添える。
  - 動きで見せる事象には、GIF を添える。
  - 画素に出ない事象には、`不要: 理由` と書く。
  - Gyazo は一斉に 404 になった (mokume-metal/works#80)。
- **CI で検める。** `pr-policy` ジョブで `python3 scripts/filing.py check` を回す。検めるのは、検査が名指しする mokume の番号のうち台帳 (`docs/filing-baseline.txt`) に無いものである。次のどれかを欠けば落とす。
  - 再現のファイル
  - 骨格
  - タイトルの API 識別子

  mokume は public なので、`contents: read` の token で本文が読める。ADR-0002 の「CI で回すのは PR の決まりごとだけ」を、起票の決まりごとまで広げる。Metal は要らない。
- **既存の起票は台帳で猶予する。** この ADR より前に名指ししていた 53 件を台帳に載せる。台帳は足さず、骨格へ移したものから消す。

手順と雛形の正本は [`docs/filing.md`](../filing.md)、段取りは skill `probes-file` に置く。

## 影響

- 物差しを足す PR が新しく名指しする起票は、骨格と再現がそろうまでマージできない。
- 起票の前に、次のものを先に作る必要がある。
  - 再現のファイル
  - `filing.py repro` の結果 (初回は mokume を組むので数分かかる)
  - 絵
- 起票した後で mokume 側の本文の区間が崩れると、次の PR の `pr-policy` が落ちる。崩れたら区間を戻すか、理由を書いて台帳へ戻す。
- 台帳の 53 件のうち open のものは、順に骨格へ移す (別の Issue で追う)。
