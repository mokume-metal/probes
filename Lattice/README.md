# Lattice — mokume v0.12.0 を条件の格子の上で、関係で突く

**作品ではなく物差しである。** 他の画素の物差しは、面 160²・`pixelDensity` 1・30 fps の
**1 点**で回し、mokume 自身の別の経路と比べる。そのため、次の 2 つが見えない。

- その 1 点の外でだけ出る破れ
- 両方の経路に共通する誤り

こちらは**条件を振り** (面の大きさ・縦横比・細かさ・fps)、**成り立つはずの関係**で比べる
(metamorphic testing)。関係は mokume の実装ではなく幾何と約束から決まるので、どの経路にも
頼らない ([ADR-0010](../docs/decisions/0010-lattice-metamorphic.md))。

## 何をしているか

| 関係 | 何と何が同じはずか |
| --- | --- |
| 鏡映・90° 回転・平行移動 | 変換を掛けて描いた絵 ↔ そのまま描いた絵を画素で写したもの |
| 切り抜き | 大きな面 (〜16384 画素) の左上 ↔ 160² の面 |
| 遠くへの平行移動 | 16384 の面の右端に描いた絵 ↔ 原点に描いた絵 |
| 細かさ = 縮小 | 細かさ 0.5 の描く面 ↔ 半分の面に `scale(0.5)` で描いた絵 |
| 細かさと光の量 | 細かさ 0.5 の太さ 1 の線 ↔ 細かさ 1 の同じ線 (置く位置を 1 画素ずつ動かす) |
| 2D と 3D | 奥行き 0 の `plane` ↔ `rect` (縦横比を振る) |
| 立体の回転 | 画面の中心で `rotateZ(90°)` した立体 ↔ 絵の 90° 回転 |
| 混ぜ方の順序 | 可換な混ぜ方で A→B ↔ B→A |
| 効果と鏡映 | 鏡映した絵に効果 ↔ 効果を掛けた絵の鏡映 (奇数・細長い面・細かさ 0.5) |
| fps をまたいだ 1 秒 | 毎秒 fps 個の粒を fps 枚 ↔ fps 個 (fps 24〜120) |

**関係の軸は、塗りと線で違う。** mokume は整数の座標を、塗りでは画素の角に、線・輪郭・点
では画素の中心に置く (mokume ADR-0039 決定 2)。そこで図形は塗りだけか線だけにし、塗りは
画素の角、線は画素の中心を軸にして写す。**座標は整数と半整数を避ける。** 三角形の経路には
縁の AA が無く (ADR-0039 決定 3)、画素の中心が縁に乗ると境界の規則が片側へ決めるためである。

| 確かめ方 | 何を通るか | 何で見るか |
| --- | --- | --- |
| `mokume run .` | 1 組ずつ、左右に 2 つの条件の絵を並べる (← → で切り替える) | 目で見る |
| `swift test` | 条件ごとに `SketchRuntime` を組み、関係を画素で確かめる | 数で比べる |

図形と条件の定義は [`Sources/Lattice/Figures.swift`](Sources/Lattice/Figures.swift) と
[`Sources/Lattice/Cases.swift`](Sources/Lattice/Cases.swift) にあり、窓もテストも同じ定義を描く。
画素の写し方は [`Tests/LatticeTests/Mapping.swift`](Tests/LatticeTests/Mapping.swift) にある。

## 走らせる

```bash
mokume run .                          # 窓で並べて見る
swift test                            # 窓を出さずに回して、関係を確かめる (十数秒)
LATTICE_DUMP=/tmp/lattice swift test  # 比べた絵を PNG で書き出す
```

**`swift test` は緑で終わる。** 破れていたものは `withKnownIssue` で包んであり、
「既知の問題」として数えられる (`v0.12.0` では 14 本のテストで 16 件)。

**mokume 側で直ると赤くなる。** 版を上げて直ったものがあると、そのテストは
「Known issue was not recorded」で落ちる。そのときは包みを外し、下の表を書き換える。

## 結果 — mokume `v0.12.0`

**14 通りの関係を突き、6 通りが約束を破っていた。** どれも 160²・細かさ 1・30 fps の 1 点では
出ない。mokume へ 6 件を起票した。

### 破れていたもの

| 鍵 | 条件 | 何が起きたか | mokume |
| --- | --- | --- | --- |
| `thinOutline` | 細かさ 0.5 | 三角形の経路 (`triangle`・`quad`・`beginShape`) の太さ 1 の輪郭が、置いた座標の偶奇で**消えるか倍の濃さ**になる。軸に沿った `quad` は偶数の y で光の量 0、奇数で 351 (細かさ 1 は 280)。距離関数の経路は一定 | [#1637](https://github.com/mokume-metal/mokume/issues/1637) |
| `upscaleKeepsPremultiplied` | 細かさ 0.5・0.75 | 拡大段 (Catmull-Rom) の行き過ぎを締めず、透明の下地で不透明度が最大 1.146、色 > 不透明度が 29 画素。負の側だけ締めるので光の量も増える (塗り +1%、細い線 +6〜8%) | [#1638](https://github.com/mokume-metal/mokume/issues/1638) |
| `effectPositionIsOutputPixels` | 細かさ 0.5 | 利用者の効果の `Pixel.position` / `size` が描く画素で渡り、8 画素の市松が 16 画素になる (説明は「効果の画素は出す画素」) | [#1639](https://github.com/mokume-metal/mokume/issues/1639) |
| `emitPerSecond` | fps 25・50・100 | 毎秒 fps 個の粒を fps 枚回すと 1 個少ない (24・49・99)。1 枚目に出ない。刻みを `Float(1/fps)` で渡すため。24・30・60・120 はちょうど | [#1640](https://github.com/mokume-metal/mokume/issues/1640) |
| `clipStaysInside` | 小数の座標・細かさ 0.5 | `clip` を細かさ 1 では切り捨て (`clip(10.9, …)` で重心が 0.9 画素寄る)、細かさ 1 未満では外向きに丸める (幅 20 が 22)。矩形の外の画素を満濃度で描く | [#1641](https://github.com/mokume-metal/mokume/issues/1641) |
| `badFrameRate` | fps 0・負 | 組み立てで断らず、黙って 1 fps で走る (`pixelDensity` の範囲外は断る) | [#1642](https://github.com/mokume-metal/mokume/issues/1642) |

### 約束どおりだったもの (陰性対照)

| 鍵 | 条件 | 確かめたこと |
| --- | --- | --- |
| `equivariance` | 図形 25 (塗り 11・線 14) × 変換 6 | 距離関数・三角形・字・曲線・穴のどれも、鏡映・90/180/270° 回転・整数の平行移動で画素ごと写り合う (差 0.004 未満)。三角形の経路の線だけ、縁の 2 画素が浮動小数の丸めで入れ替わる |
| `cropInvariance` | 161²・160×997・997×160・16384×200・200×16384 | 左上 160² が同じ絵。200×16384 では三角形の経路の塗りの縁が 1 画素入れ替わる |
| `farTranslation` | 4096² の (3900, 3900)・16384×200 の (16200, 20) | 遠くへ動かしても 1 画素も違わない |
| `densityIsScale` | 細かさ 0.5・塗り 11 | 描く面が、半分の面に `scale(0.5)` で描いた絵とバイトで一致する |
| `planeMatchesRect` | 160²・161×97・97×161・1001×31・31×1001 | 回した `plane` と `rect` が、50% の白黒で 1 画素も違わず、重心も 0.1 画素以内 (ADR-0039 決定 1) |
| `solidRotation` | 160²・161² | 立体 (箱と球・視線に沿った光) の `rotateZ(90°)` が絵の回転と一致する |
| `blendCommutes` | add・multiply・screen・exclusion・darkest × 下地 2 | 重ねる順を入れ替えても同じ絵 |
| `effectsMirror` | 効果 6 × 面 3 × 細かさ 2 | blur (小・大)・bloom・vignette・fringe・adjust が鏡映と入れ替えられる |

`thinOutline` と `clipStaysInside` は、同じ検査の中に破れない条件 (距離関数の経路・整数の
矩形) を包まずに置き、対照にしている。

### 当たりを付けたが起票しなかったもの

| 当たり | 起票しなかった理由 |
| --- | --- |
| `difference`・`lightest` の順序 | 縁の被覆と半透明のもとでは、式そのものが可換でない |
| `fringe` のずれが長辺の 2% まで届く | 「短辺の割合」は内部のコメントだけで、公開の説明は「色をずらす」 |
| 細かさを下げると小さな形の重心が動く (≤ 0.03 画素、7×5 の面の端で 0.13) | 描く大きさを縦横別々に丸めることは説明済み |
| `wander` の効きが fps で変わる・寿命 < 1/fps の粒が描かれない | 力の離散化は説明が式を約束している (ADR-0025 決定 6)。後者は「進めて描く」と説明にある |

## どうやって当たりを付けたか

mokume `v0.12.0` のソースを、細かさ・面の大きさに依る所と、fps・時間に依る所に分けて
読んだ。そのうえで、使い捨ての舞台で関係を先に広く回した (図形 25 × 変換 6 × 面 9 通り・
細かさ 3 通り・fps 7 通り)。破れた関係は、約束の出典 (説明文・ADR) があるものだけを残した。

## どの mokume で測ったか

**`Package.resolved` が固定している版がそのまま答えで、コミットしてある** (`v0.12.0` =
`bab3b4a`)。`from: "0.12.0"` は他の物差しと同じく記録であって、留め金ではない。

版を上げたら `swift test` を回す。**赤くなったテストは、直った約束である。**
