# Churn — mokume v0.22.0 で「足し・消し・動かし続けた」絵が履歴・数・同一性に引きずられないかを突く

**作品ではなく物差しである。** 負荷は軽いまま、物体を毎フレーム足し・消し・動かし続ける。そのとき、ある枚の絵が
**その枚の描画命令だけで決まっているか**を見る。

- 前のフレームまでの履歴に引きずられていないか。
- 同じフレームの他の物体の数に引きずられていないか。
- 捨てた物体の同一性 (アドレス) に引きずられていないか。

動かし続けるスケッチで崩れるバグは、1 枚だけ描く検査には掛からない。崩れ方は 3 つの型に分かれる。

- **控え (キャッシュ) が古いまま使われる。** 例: 消えた物体の控えを、次に生まれた物体が引き継ぐ。
- **数で経路が切り替わり、切り替わりの前後で絵が変わる。** 例: 同じ形の 2 つ目から GPU で置く。
- **まとめて描くと、1 つずつ描いたときと順序が変わる。** 例: まとめた置き場所を、形の領域ごとに回す。

## 何をしているか

**候補 1 件を、1 つのことだけが違う 2 つの経路で描く** (`Relation`)。

| 関係 | 左 (`suspect`) | 右 (`reference`) | 比べるもの |
| --- | --- | --- | --- |
| history (履歴) | 前置きの 8 枚にがらくたを描く。描き場所・粒の群を作っては捨て、文字の大きさ・影・断片を変える | 前置きの 8 枚は `background` だけ | 前置きの後の 6 枚。フレーム番号と `randomSeed` を揃えるので、時刻を読む断片も粒も同じになるはず |
| fresh (積み重ね) | 種から作った増減・移動の列を、1 つの runtime で回す | 同じ場面を 1 枚ずつ、新しい runtime の 1 枚目として描く | 全部の枚。時刻を読まない場面に限る |
| locality (数) | 左に A を置き、右に足す数を毎フレーム変える (0〜16385。経路が数で切り替わる境目を往復する) | A だけ | 左の列 (A の領域) だけ |
| equivalence (置き方) | まとめて描く (`shape(_:at:)` に置き場所を並べる・捨てた描き場所の後に作った描き場所) | 1 つずつ描く (`shape` を置き場所ごとに呼ぶ・別の描き場所に描く) | 全部の枚。置き場所は毎フレーム動き、重なり方が変わる |

食い違えば、絵がその 1 つのことに引きずられている。

| 確かめ方 | 何を通るか | 何で見るか |
| --- | --- | --- |
| `mokume run .` | 窓の経路。1 候補ずつ、左右に 2 経路の絵を並べる (← → で切り替える) | 目で見る |
| `swift test` | 窓を出さない経路。`SketchRuntime` を経路ごとに組み、N 枚回す | 画素を読んで数で比べる |

組み立てと比べ方は、[Weave](../Weave/) と同じである。

- **経路ごとに別の `SketchRuntime` で回す。** fresh の参照だけは、1 枚ごとに runtime を組み直す。
- **比べるときの許容はほぼ 0 にする** (成分の差 0.004 = 表示の 1 段未満)。同じ機械・同じフレーム番号からは、
  バイト単位で同じ絵が出る約束 (mokume ADR-0001 原則 2) があるためである。
- **各検査は、比べる前に参照の側が描けていることを押さえる。** この押さえは `withKnownIssue` の外に置く。
  参照まで描けていないことを、既知の問題に数えないためである。
- **突く側が実際に突いていることも押さえる。** そうでないと、左右が一致しても何も言えない。
  - history: 前置きで 2 経路の絵が違うこと。
  - locality: 右に足した物体が描けていること。
  - history の後の場面: 粒が描けていること。
  - `graphicsReuse`: `ObjectIdentifier` の引き継ぎが起きたこと。
- **場面は種から作る。** history と fresh は種 1・2・3 で回す。乱数は mokume の `random` を使わない
  (粒が同じ流れを読むので、場面を作るだけで粒の絵が変わってしまう)。
- **陰性対照を置く。** `historyBlank` は前置きがどちらも空で、判定そのものの押さえである。破れなかった候補も
  そのまま陰性対照として残す。

候補の定義は [`Sources/Churn/Cases.swift`](Sources/Churn/Cases.swift)、場面と描き方は
[`Sources/Churn/Scenes.swift`](Sources/Churn/Scenes.swift) にあり、窓もテストも同じ定義を描く。

## 走らせる

```bash
mokume run .                          # 窓で並べて見る
swift test                            # 窓を出さずに回して、画素で比べる
CHURN_DUMP=/tmp/churn swift test      # 比べた最後の絵を PNG で書き出す
PROBES_SHOTS=/tmp/shots swift test    # 読んだ絵を全部 /tmp/shots/Churn/<名前>-<フレーム>.png に書き出す
```

**`swift test` は緑で終わる。** 破れていたものは `withKnownIssue` で包んであり、「既知の問題」として
数えられる (`v0.22.0` では 12 本のテストで 5 件)。

- 3 件は候補の検査の分である (`shapeAtRegions`・`shapeAtTranslucent`・`graphicsReuse`)。食い違ったフレームは 1 つの期待に
  まとめて数える。
- 2 件は、起票に貼った再現 (`Tests/ChurnTests/Repros/`) をそのまま走らせる `ReprosTests` の分である
  ([docs/filing.md](../docs/filing.md))。

**`scripts/stress.py Churn --repeat 3 --workers 3` (`v0.22.0`) は、15 回とも通過し、既知の問題は毎回 5 件で揺れなかった。**
指紋は、影を落とす 3D の場面 (`history3DShadows`・`fresh3D`・`localityShadow`) で、検証レイヤの 3 回だけが多数派と違った。

- 切り分けると、`MTL_SHADER_VALIDATION=1` だけで出て、`MTL_DEBUG_LAYER=1` だけでは出ない。
- 違いは 1 枚に 1〜3 画素、成分の差は最大 0.0007 (表示の 1 段未満)。
- 断片の計装でシェーダが組み直され、浮動小数の丸めが変わったものと読み、mokume の破れには数えていない
  (ADR-0007 の「同じ機械」は、同じ組み立てのシェーダを前提にしている)。

**mokume 側で直ると赤くなる。** 版を上げて直ったものがあると、そのテストは「Known issue was not recorded」で
落ちる。そのときは包みを外し、下の表を書き換える。

## 結果 — mokume `v0.22.0`

**17 件を突いて、3 件が約束を破っていた。** 根は 2 つなので、mokume へ 2 件の Bug を起票した。履歴・積み重ね・数の 11 件と、置き方の陰性対照
3 件は、1 画素も違わなかった。

## どうやって当たりを付けたか

mokume `v0.22.0` のソースを 3 方面に分けて読んだ。

- **控えと同一性。** `ObjectIdentifier`・ハッシュ・版の印で引く控え (影の焼き直し・保持した形・字の面・描き場所の写し)。
- **毎フレームの置き場と列。** 置き場の初期容量と倍の取り直し、列の分け方、数で切り替わる経路
  (平面の畳み・裏 → 表をまとめる経路・1 列の上限)。
- **資源の寿命。** 粒の群・描き場所・字の面・光を、作っては捨てる。

読んだのは、**ある枚の絵が、その枚の描画命令の外にある何に依りうるか**である。当たりは、公開の口だけで画素から判定できる
形に組み直した。数で切り替わる経路は、境目の値を mokume のコードから拾い、`counts` / `capCounts` で往復させている。

**破れの 2 件は、どちらも「1 つずつなら正しい」所にあった。**

- `shape(_:at:)` は置き場所が 1 つなら正しく、領域が 1 つでも正しい。置き場所が 2 つ以上・領域が 2 つ以上・置き場所が重なる、の 3 つが揃って初めて出る。
- 描き場所の写しは、捨てずに使い回すスケッチでは正しく、`Canvas` のアドレスが使い回されたときだけ外れる。mokume 自身も
  `PendingUploads.swift` で「`ObjectIdentifier` で見分けないのは、死んだ持ち主の番号が新しい持ち主に使い回されうるから」と書いており、
  同じ危うさを別の場所では避けている。

### 当たりを付けたが突かなかったもの

| 当たり | 突かなかった理由 |
| --- | --- |
| 自分自身を置く (`pg.image(pg, …)`) で「`endDraw()` の前に置いた」警告が出ない | 画素はパス開始前の絵で、Metal の検証レイヤも何も言わなかった。絵の破れではなく警告の欠けで、動かし続ける観点からも外れる。Weave も同じ理由で突いていない |
| `createShape` の中の大きな字で字の面を焼き直すと、次のフレームの焼き直しの枠を使い切る | 筋道はコードで追えたが、4096 の面を埋めたうえで、ループ中の入力の受け口で `createShape` を呼ぶ形が要る。作品の書き方から遠いので、次の版の候補にする |
| 1 フレームに描き場所を 5 回以上描き換えて置く (写しの上限 4) | 6・8 回で試し、置いた時点の絵がどれも出た。説明の「越えた分は描き切る」と実際の描き切りの回数は違うが、絵は約束どおり |
| 細い塗りの判定が CPU と GPU で式が違う (境目の幅の矩形) | 境目の幅を振った `localityFolding` の範囲では 1 画素も動かなかった。式の差を画素に出す形が定まらない |

## どの mokume で測ったか

**`Package.resolved` が固定している版がそのまま答えで、コミットしてある** (`v0.22.0` = `c1e0f6b`)。
`from: "0.22.0"` は他の物差しと同じく記録であって、留め金ではない。破れの 2 件は、mokume の `main` (`ff89651`) でも
再現が単独で出ることを確かめた (`python3 scripts/filing.py repro Churn <鍵> --mokume main`)。

版を上げたら `swift test` を回す。**赤くなったテストは、直った約束である。**
